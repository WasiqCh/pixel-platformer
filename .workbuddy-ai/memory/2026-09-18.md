## Fixed: "Network error: Unexpected end of JSON input" on channel create

**Root cause:** `frontend/vite.config.js` proxied `/api` -> `http://localhost:8000`,
but the backend runs on **8100**. POST /api/v1/channels never reached uvicorn, so the
frontend got an empty body and failed parsing it.

- Backend was intentionally moved 8000 -> 8100 (Task Tracker.md:51, port collision with
  another local project). The vite proxy was never updated — docs (BUILD_PLAN.md,
  implementation_plan.md) still say :8000 too.
- Fix: changed proxy target to `http://localhost:8100`. Verified GET through :3000
  returns real channel data.
- Diagnostic trick that found it fast: the uvicorn log showed NO incoming channel
  request at all — only /docs. Empty-body JSON errors + zero backend log entries =
  request never arrived, so suspect the proxy/base URL, not the endpoint.

### Dependency notes
- `openai==3.6.0` depends on `httpx2` (pydantic-published successor to httpx), NOT
  `httpx`. Both are installed and that is expected, not a typosquat. The backend's own

- Known environment trap: the venv can drift behind requirements.txt. If a fresh

## Bug: compose -> 500 "Internal Server Error" (FIXED)

- `backend/api/prompts.py:198` `char_action_counter[ref] += 1` -> `KeyError: 'RW01'`.
  Counter is seeded from `characters` only, but world records (RW*/MT*) can also be
  classified `dynamic` by `base_class()`. Only projects with an RW/MT asset in a beat
  crash - that's why CH03_EP02 failed while the other 3 passed.
- Fix: `char_action_counter[ref] = char_action_counter.get(ref, 0) + 1`.
  Verified: CH03_EP02 compose now 200 -> 42 generations (24 dynamic, 18 masters).

## Bug: dispatch_stream broken (FIXED)

- `backend/core/llm_client.py` did `async for frame in _with_backoff(_inner())`.
  `_with_backoff` awaits a coroutine, but `_inner()` is an async generator ->
  `TypeError: 'async for' requires __aiter__, got coroutine`. Broke streamed
  `script_draft` (script writing). Fixed by dropping the backoff wrapper for streams
  and just holding the semaphore; `_inner()` already yields its own error frames.

## Environment gotchas (cost a lot of time)

- **`uvicorn --reload` is unreliable here**: it watches the whole repo incl.
  node_modules (1700+ files) and silently misses edits. Three separate "my fix
  didn't work" investigations were just stale code. Use
  `uvicorn ... --reload --reload-dir backend`, or restart explicitly to verify.
- **HTTP_PROXY/HTTPS_PROXY are set to 127.0.0.1:56464**. The OpenAI SDK honours
  them, so calls to a localhost LLM endpoint fail with APIConnectionError on
  large (sharded) payloads while tiny ones pass. Fixed in `_client()` with
  `httpx2.AsyncClient(trust_env=False)`.
- Same fix pattern for curl: always `--noproxy '*'` when probing localhost.
- Free/weak models return structured JSON where the recipe asks for a string.
  Added tolerant validators in models/character.py (`_flatten`, key-variant
  mapping for mentions) so one malformed field doesn't fail the whole extract.
  Same treatment applied to models/world_record.py (text/type coercion +
  normalising invented `type` values onto the real vocabulary).

### Environment gotchas
- `curl` in this shell goes through a proxy and returns bogus 502s for localhost.
  Use `curl --noproxy '*'` when probing local servers.
- Vite binds to IPv6 loopback; `http://[::1]:3000` and `http://localhost:3000` work,
  plain `http://127.0.0.1:3000` is refused.
- **`shutil.rmtree` is intercepted by the agent sandbox's safe-delete shim**
  (`sitecustomize.py`). Deleting >50 files raises `SystemExit(1)` with
  `[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]` instead of removing anything.
  This makes app code that bulk-deletes look like it 500s. ALWAYS check whether a
  delete-related 500 is really the app before "fixing" it. Reproduce in-process with
  `fastapi.testclient.TestClient(app, raise_server_exceptions=True)` to see the real
  traceback — the running uvicorn's stderr is not reachable from this shell.

### Diagnostic techniques worth reusing
- **Probe whether the server has your new code**: hit an endpoint whose behaviour you
  changed and compare (e.g. old delete returned 200 for a missing id, new returns 404).
  Faster and safer than restarting blind.
- **Get a traceback from a running server**: you cannot read uvicorn's stderr from this
  shell, so start a second instance via `run_in_background` and read `TaskOutput`, or
  drive the app in-process with `TestClient`.

- GET /api/v1/recipes — all 18 jobs with tier/temp/stream/versions

### "Resume from last good state" — user was RIGHT
